**ผู้ใช้สั่งไว้ 2026-09-25**: *"ตัดออกเลยครับ ถ้าไม่ใช้ควรเอาออกเสมอ เพือลด process"*

ตอนเจอว่าสัญญามีกติกาที่ไม่มีใครใช้ **ทางเลือกตั้งต้นคือตัดทิ้ง ไม่ใช่ทำให้มันครบถ้วนขึ้น**

**Why**: ผมเจอว่า `asyncapi.yaml` ไม่มีกติกา routing key ที่สเปกฉบับคนบังคับไว้ แล้วเสนอ *"เติมลง asyncapi + ทำให้ key ว่างขึ้น alert"* — คือขยายกติกาที่ไม่ควรมีตั้งแต่แรก · ผู้ใช้เลือกตัดทิ้งแทน (G83)

**How to apply**
- เจอความไม่ตรงกันระหว่าง 2 ชั้นเอกสาร ⇒ **ถามก่อนว่ากติกานั้นยังจำเป็นไหม** ก่อนจะเสนอวิธีทำให้ตรงกัน
- สัญญาณว่าควรตัด: **ค่าที่ derive จากข้อมูลที่ส่งมาด้วยกันอยู่แล้ว** ⇒ ปลายทางต้องเขียน logic ซ้ำ และมันทำได้อย่างเดียวคือไม่ตรงกัน
- สัญญาณอื่น: ไม่มีโค้ดตรงไหนอ่าน · ตัวตรวจที่จับเคสที่น่าจะเกิดที่สุดไม่ได้ · เหตุผลที่บันทึกไว้เดิมพอไปตรวจของจริงแล้วไม่จริง
- **ไปตรวจเหตุผลเดิมของมันเสมอ** — G67 เขียนว่า *"ราคาฝั่ง vendor ≈ 0"* และ *"ดูจาก broker ได้โดยไม่ต้องเปิด payload"* ทั้งคู่ไม่จริงพอไปดูของจริง
- ตัดแล้วต้องตามเก็บให้ครบ: สเปกทุกฉบับ (md · yaml · html) · enum/CHECK ในฐาน (ต้องมี migration) · **จำนวนที่เอกสารอื่นอ้างถึง** (เช่น "32 alert code" ต้องเป็น 31)
